4. AUTHENTICATION AND SESSION MANAGEMENT
==================================================

Implement authentication that follows the backend contract.

The backend issues:

- A short-lived JWT access token in the login and refresh response.
- A rotating refresh token in an HttpOnly, Secure cookie.

FRONTEND RULES:

1. Never store access tokens in localStorage or sessionStorage.

2. Never attempt to read or manually handle the HttpOnly refresh-token cookie.

3. Keep the access token in memory.

4. Implement session initialization and recovery using the refresh endpoint.

5. Use a centralized request client that attaches the access token.

6. When the access token expires, coordinate a single refresh request and retry the original request once when appropriate.

7. Prevent simultaneous failed requests from triggering multiple independent refresh-token rotations.

8. Do not retry a failed refresh indefinitely.

9. If the session is invalid or revoked, clear the in-memory authentication state and redirect the user to login.

10. On logout, call the backend logout endpoint and clear authentication-related client state and caches.

11. Never expose JWTs, customer identification details, or financial data in browser logs.

12. Do not rely on client-side route protection as a substitute for backend authorization.

DEPLOYMENT CONTRACT:

Prefer a same-origin deployment:

/          → Next.js frontend
/api/v1    → Express backend through a trusted reverse proxy

The browser should call relative /api/v1 endpoints.

The refresh cookie must be configured consistently with the backend and reverse-proxy path.

Ensure login, refresh, and logout work correctly in both development and production.

If a separate-origin deployment is required, document and implement its cookie, CORS, credentials, and CSRF strategy explicitly.

AUTHENTICATION UI:

Create:

- Professional login page.
- Forgot-password page.
- Reset-password page.
- Change-password interface.
- User profile.
- Session-expired state.
- Unauthorized access page.
- Appropriate session initialization loading state.

Avoid showing the login page briefly to an already authenticated user while session recovery is underway.
